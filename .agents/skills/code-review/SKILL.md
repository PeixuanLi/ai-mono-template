# 代码评审

机器查格式,人查逻辑;CI 已把关的事(格式、预算、笔记格式)不必重复看。

## 评审前三查

1. **世界验证**:新增/修改的测试是否断言外部可观察状态(返回值、文件内容、退出码)?
   反例信号:断言实现的形状(`toHaveProperty`)、只断言 mock 被调用、测试重述实现代码。
2. **笔记保鲜**:本 PR 是否使某篇笔记的结论过时?过时 → 同 PR 更新或归档;
   本 PR 是否做出有取舍的新决策?是 → 补笔记(含替代方案)。
3. **slop/CoT 痕迹**:文档/注释里是否有推理转录("我们首先…然后…")、重复规则、强调通胀、
   无法解析的引用?判据:HEAD 上的读者不访问会话记录能否核实每句话。

## 产出格式

区分"必须改"与"建议改";必须改的给出文件与行号,建议改的说明理由。
